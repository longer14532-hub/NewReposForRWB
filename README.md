# NewReposForRWB
# Гибридная Mesh-доставка WB: разгрузка хабов и экономия на локальной логистике

Проект для хакатона Университета RWB (Wildberries) и ПГТУ в номинации **«ТОП ИИ ПРО»**.

## Суть решения
Классическая модель доставки заставляет локальные заказы (где товар и покупатель находятся в одной агломерации) совершать лишний логистический крюк через загородный фулфилмент-хаб (промпарк «Зеленодольск», 20) и обратно.

Мы предлагаем **управляемый кластерный Mesh** с гибридной маршрутизацией (**Shadow Routing**):
- **Опорные ПВЗ (~15% сети, 125 точек в Казани):** крупные пункты выдачи с 5 м² свободной подсобки, стоящие **первыми** на утреннем маршруте WB Drive.
- **3 сценария доставки:**
  1. `Zero-Leg` (20%) — выдача напрямую с полки Опорного ПВЗ (24/7).
  2. `1-Hop Milk-Run` (45%) — попутная развозка водителем WB Drive вниз по маршруту без лишнего пробега.
  3. `1-Hop Шаттл` (35%) — локальный курьер внутри микрокластера (7–8 ПВЗ).
- **Shadow Routing (Гибридный роутер):** если партия не набирает порог окупаемости $N_{\min}$, товар не проходит 4 фильтра (КГТ, белый список, цена, оборачиваемость), полка заполнена > 80% или заказ падает в вечерний межрайон — заказ автоматически уходит по классической схеме через Хаб.
- **Операционные предохранители (Guardrails):** приёмка/вывоз строго в офф-пик (10:00–16:00), мастер-короба с номерными пломбами (`seal_code`, передача ≤ 60 сек), *Smart Return-to-Shelf* (возврат на полку только при целой заводской пломбе + фотофиксации) и прогрессивный тариф хранения от неликвида с автовывозом на 30-й день.

## Архитектура проекта

| Модуль | Описание |
| :--- | :--- |
| `config.py` | Единый источник всех бизнес-допущений, тарифов, коэффициентов, геокоординат и ограничений (ноль магических чисел в коде). |
| `finance_engine.py` | Чистое расчётное ядро на `dataclasses` / `Pydantic` (без привязки к ноутбуку и визуализации). Расчёт $C_{\text{хаб}}(d)$, $C_{\text{Mesh}}$, порога окупаемости $N_{\min}(d)$, Blended Unit Cost, Net Savings, ROI/NPV и физики 5 м². Покрыто юнит-тестами. |
| `geo_kazan.py` | Парсинг реальной сети ПВЗ Казанской агломерации через OpenStreetMap Overpass API (с автоматическим фоллбэком), кластеризация, выбор Опорных ПВЗ, расчёт плеч от Зеленодольска и генерация интерактивной карты `kazan_mesh_map.html` + `kazan_network.json`. |
| `simulation.py` | Почасовая дискретно-событийная симуляция в 3 режимах (`Baseline`, `Basic Mesh`, `Smart Mesh`) на бенчмарке из 500 заказов и 30-дневной модели города с проверкой всех guardrails через `assert`. |
| `report.py` | Экспорт графиков (PNG 300 DPI), Tornado-диаграммы чувствительности, точек слома модели, таблицы Decision Rules по районам и сводных отчётов в CSV/Excel. |

## Ключевые показатели модели (Казанская агломерация)

- **Масштаб рынка:** ~1 375 000 заказов WB в месяц (население 1,72 млн, ~830 ПВЗ в агломерации).
- **Целевой поток через Mesh:** ~122 600 заказов/мес (8,9% от всех заказов города после фильтрации и отсечек гибридного роутера).
- **Экономика Опорного ПВЗ:** вместимость до 250 SKU (при заполнении ≤ 80% на 5 м²), оборачиваемость 4 об./мес (1 000 заказов/мес), дополнительный доход партнёра **24 000 ₽/мес** (при целевом пороге ≥ 20 000 ₽/мес).
- **Базовая себестоимость плеча Хаба (d = 35 км):** 74,43 ₽ (прямое плечо) + 6,68 ₽ (ожидаемый возврат).

## Быстрый старт

### 1. Установка зависимостей
Рекомендуется Python 3.10+ или среда Google Colab:
```bash
pip install numpy pandas scipy pydantic folium requests openpyxl matplotlib seaborn pytest
```

### 2. Запуск юнит-тестов финансового ядра
```bash
pytest test_finance_engine.py -v
```

### 3. Генерация геосети, запуск симуляции и отчётов
```bash
python geo_kazan.py      # Формирует kazan_network.json и kazan_mesh_map.html
python simulation.py     # Запускает бенчмарк 500 заказов и 30-дневную модель
python report.py         # Генерирует графики PNG 300 DPI и таблицы Excel/CSV
```
